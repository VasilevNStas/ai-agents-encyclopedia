# Финальный экзамен — 10 практических заданий

> [!important] Инструкция
> Каждое задание выполняется в OpenCode. Ассистент (профессор) помогает, но не решает за студента. Задание считается пройденным, когда студент может объяснить КАЖДУЮ строку своего решения.

---

## Задание 1: Анатомия промпта (Модуль 6)

Напиши system prompt для агента, который проверяет код на уязвимости. Используй все 6 элементов RCTFCE.

**Критерии:**
- Role определён
- Context передан (что за проект, какие языки)
- Task сформулирован императивно
- Format указан (JSON)
- Constraints есть (чего НЕ делать)
- Examples есть (1-2 примера)

## Задание 2: ReAct-цикл (Модуль 1)

Напиши псевдокод (или Python) цикла ReAct-агента для задачи:

> «Найди все файлы .env в проекте, проверь, нет ли в них паролей, и если есть — замени на *****»

Опиши каждый шаг: Thought → Action → Observation.

## Задание 3: Память (Модуль 3)

Спроектируй класс AgentMemory для задачи из Задания 2.

- Short-term: что хранится в messages[]?
- Working: какой JSON хранит состояние задачи?
- Long-term: что сохранить после завершения?

Напиши код класса.

## Задание 4: Plan-and-Solve (Модуль 2)

Составь план для задачи «провести code review 10 файлов проекта»:

1. Напиши план (5-7 шагов)
2. Опиши, при каком условии план нужно скорректировать
3. Что будет trigger для replanning?

## Задание 5: Guardrails (Модуль 5)

Спроектируй систему guardrails для GitHub-агента, который имеет доступ к:

- Чтению репозитория
- Созданию PR
- Мержу PR
- Деплою на production

Для каждого действия укажи: allow / confirm / block / escalate.

## Задание 6: Tool Design (Модуль 2, 6)

Спроектируй инструмент `send_email` для агента:

- Напиши JSON Schema с параметрами (to, subject, body, attachments)
- Какие параметры обязательные, какие опциональные?
- Какие guardrails нужны?
- Что должно быть в description для каждого поля?

## Задание 7: Structured Output (Модуль 6)

Напиши JSON Schema для инструмента `create_bug_report`, который агент вызывает после нахождения бага.

Схема должна включать:
- file (string, обязательный)
- line (number, опциональный)
- severity (enum: low/medium/high/critical)
- description (string, обязательно)
- suggested_fix (string, опционально)
- affected_tests (array of strings, опционально)

## Задание 8: Resilience (Модуль 5)

Перепиши следующий агент, добавив ему resilience:

```python
def agent(task):
    response = llm.generate(task)
    result = execute_tool(response)
    return result
```

Добавь:
- Retry с backoff
- Fallback модель
- Cost controller (лимит $0.05)
- Graceful degradation

## Задание 9: RAG Pipeline (Модуль 3)

Спроектируй RAG-пайплайн для базы знаний из 5000 статей.

Ответь на вопросы:
1. Какой размер чанка выберешь и почему?
2. Нужен ли hybrid search или хватит semantic?
3. Какой метод reranking выберешь?
4. Как будешь определять, что RAG выдал неверный ответ?

## Задание 10: Финальный проект (все модули)

Собери агента с нуля, который:

1. Принимает на вход ссылку на GitHub репозиторий
2. Клонирует его
3. Находит все TODO/FIXME комментарии
4. Создаёт отчёт с файлами, строками и приоритетами
5. Сохраняет отчёт в wiki проекта
6. Отправляет summary в чат (симуляция)
7. Укладывается в бюджет $0.10
8. Имеет guardrails на каждое действие

**Формат сдачи:** Python-скрипт (`final_agent.py`) + лог выполнения.

## Задание 11: A2A — Agent-to-Agent Protocol (Модуль 4)

Спроектируй взаимодействие двух агентов по протоколу A2A:

> Агент A (исследователь) нашёл уязвимость в коде. Ему нужно отправить задание агенту B (разработчику) на исправление. После исправления — агент C (тестировщик) проверяет фикс.

Опиши:
1. Agent Card для каждого агента (skills, capabilities, rate limits)
2. Формат A2A-сообщения (task → status → result → error)
3. Как агенты находят друг друга (Agent Discovery)
4. Что будет, если агент B не отвечает (timeout, retry, escalate)

**Формат:** JSON-схемы сообщений + текстовое описание потока.

## Задание 12: AI Gateway & Model Routing (Модуль 8)

Спроектируй gateway для AI-агента с бюджетом $5/день:

**Условия:**
- Три модели: GPT-4o ($10/1M ввод), Claude Haiku ($0.25/1M), DeepSeek V3 ($0.50/1M)
- Средний запрос: 2000 вводных + 500 выходных токенов
- Нагрузка: пиковые часы (10-12, 14-16) x3 от базовой
- 90% запросов терпят задержку до 2 секунд, 10% — до 10 секунд

**Спроектируй:**
1. Routing rules (какие запросы на какую модель)
2. Fallback цепочку
3. Cost controller (что происходит при превышении бюджета)
4. Кэш-стратегию
5. Rate limiter (RPM, burst)

**Формат:** таблица rules + псевдокод router().

---

## Задание 13: Streaming & Real-Time (Модуль 9)

Спроектируй real-time агента для голосового ассистента в колл-центре:

**Требования:**
- 500 параллельных сессий
- WebSocket + SSE для стриминга
- ASR (речь→текст), LLM, TTS (текст→речь)
- Латентность: отклик < 500ms (first token), полный ответ < 3s
- Interruption handling (клиент перебивает агента)

**Опиши:**
1. Архитектуру потоков данных
2. Обработку interruption (как агент «затыкается» и слушает)
3. Как синхронизировать стейт между сессиями
4. Механизм backpressure при перегрузке

**Формат:** диаграмма (текстовая), sequence diagram, ключевые структуры данных.
