# Урок 9: LLM Wiki — альтернатива RAG по Карпати

> [!quote] Ключевая идея
> Вместо того чтобы каждый раз искать по сырым документам (RAG), LLM **сама ведёт и поддерживает Wiki** — структурированную базу знаний в markdown-файлах. Это как если бы у тебя был личный ассистент, который читает книгу, а потом пишет по ней конспект и обновляет его, когда появляются новые главы.

---

## Проблема RAG

RAG (из предыдущего урока) хорош, но у него есть фундаментальная проблема:

> RAG **каждый раз переоткрывает знание заново**.

Ты задаёшь вопрос. RAG: ищет чанки → склеивает → подаёт LLM → LLM синтезирует ответ. На следующий день ты задаёшь похожий вопрос — RAG делает то же самое с нуля.

**Ничего не накапливается.** Каждый запрос — «чистый лист».

---

## Что предлагает Карпати (Andrej Karpathy)

Вместо RAG — **LLM Wiki**:

```
RAW SOURCES                  WIKI
(статьи, коды,         ──→   (markdown-файлы,
 PDF, всё сырьё)               LLM пишет и ведёт)
       │                          │
       │                    СХЕМА (AGENTS.md)
       │                    правила: как писать,
       │                    как обновлять, как
       │                    ссылаться
       ▼                          ▼
    Immutable               Compounding knowledge
    (LLM читает,            (знание накапливается
     но не пишет)            и связывается)
```

Три слоя по Карпати:

| Слой | Что это | Кто владеет |
|------|---------|-------------|
| **Raw sources** | Сырые документы (статьи, PDF, код) | Ты (read-only для LLM) |
| **Wiki** | Markdown-файлы: сущности, концепции, сравнения | LLM (создаёт и обновляет) |
| **Schema** | AGENTS.md — правила, как структурировать вики | Вы оба (эволюционирует) |

## Как это работает на практике

```python
# ШАГ 1: Ингест (ты добавляешь новый источник)
def ingest(source_path: str):
    """LLM читает источник и обновляет Wiki."""

    source = read_file(source_path)

    # LLM анализирует и решает, какие страницы обновить
    plan = llm.generate(f"""
    Прочитай новый источник:

    {source}

    Какие страницы Wiki нужно создать или обновить?
    Перечисли в формате:
    - CREATE wiki/concepts/{topic}.md — новая концепция
    - UPDATE wiki/entities/{name}.md — новые данные
    """)

    for action in parse_plan(plan):
        if action.type == "CREATE":
            write_file(action.path, action.content)
        elif action.type == "UPDATE":
            update_wiki_page(action.path, action.content)
```

```
Пример: ты добавляешь статью про DeepSeek-R1.

LLM:
  1. Создаёт wiki/models/DeepSeek-R1.md
     — архитектура MoE
     — дата выхода: 2025
     — ключевые метрики
  2. Обновляет wiki/concepts/MoE.md
     — добавляет DeepSeek-R1 как пример
  3. Обновляет wiki/index.md
     — добавляет ссылку на новую страницу
  4. Пишет в log.md
     — "2026-05-08: добавлена статья DeepSeek-R1"
```

## Чем LLM Wiki лучше RAG

| Критерий | RAG | LLM Wiki |
|----------|-----|----------|
| Каждый запрос | Ищет по сырцам | Читает готовую страницу |
| Связи между фактами | Нет (чанки изолированы) | Есть (cross-reference) |
| Противоречия | Не видит (один чанк) | Может заметить и пометить |
| Накопление знаний | Нет | Да (wiki богатеет) |
| Скорость ответа | Медленно (поиск) | Быстро (чтение) |
| Точность | Зависит от чанков | Выше (синтез уже сделан) |

**Главное преимущество:** знание **компилируется один раз** при ингесте, а не синтезируется заново на каждый запрос.

## Обязательные файлы Wiki

### index.md — навигация

```markdown
# Index

## Модели
- [[DeepSeek-R1]] — архитектура MoE, 2025
- [[GPT-4o]] — мультимодальная, 2024

## Концепции
- [[MoE]] — Mixture of Experts
- [[RAG]] — Retrieval-Augmented Generation

## Источники
- [[paper-deepseek-r1]] — оригинальная статья
```

### log.md — хронология

```markdown
## [2026-05-08] ingest | Статья DeepSeek-R1
  Создано: models/DeepSeek-R1.md
  Обновлено: concepts/MoE.md, index.md

## [2026-05-07] query | "Что такое MoE?"
  Создано: concepts/MoE.md
```

## Когда LLM Wiki, когда RAG

| Сценарий | RAG | LLM Wiki |
|----------|-----|----------|
| Много сырых документов | ✅ | — |
| Часто обновляемые данные | ✅ | — |
| Исследование темы (недели/месяцы) | — | ✅ |
| Личная база знаний | — | ✅ |
| Нужны цитаты из原文 | ✅ | — |
| Нужен синтез из 10 источников | — | ✅ |

> [!tip] Идеальный вариант
> RAG для поиска по сырцам + LLM Wiki для накопления синтезированного знания. Два инструмента, которые дополняют друг друга.

## Резюме

```
RAG:      храни сырцы → ищи при каждом запросе
LLM Wiki: храни сырцы → LLM компилирует в wiki → читай wiki при запросе

RAG хорош для поиска.
LLM Wiki хороша для накопления.
Вместе — лучше.
```
