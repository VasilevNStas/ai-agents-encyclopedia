# Урок 22: Few-shot и Chain-of-Thought

> [!quote] Ключевая идея
> LLM лучше делает то, что видела в примерах (few-shot). А если попросить её «думать вслух» (Chain-of-Thought), качество рассуждений растёт — даже если модель не обучалась на этой задаче.

---

## Zero-shot vs Few-shot

**Zero-shot:** промпт без примеров. Модель делает то, что умеет по обучению.

```
Переведи на русский: "Hello, world!"
→ "Привет, мир!" ✅ (модель умеет перевод)
```

```
Напиши функцию на Python, которая сортирует список чисел.
→ ... ✅ (модель умеет писать код)
```

**Few-shot:** 2-5 примеров в промпте. Модель «понимает» формат задачи.

```
Вопрос: "Какая столица Франции?"
Ответ: "Париж"

Вопрос: "Какая столица Германии?"
Ответ: "Берлин"

Вопрос: "Какая столица Италии?"
→ "Рим" ✅ (модель продолжила паттерн)
```

---

## Когда few-shot необходим

| Ситуация | Zero-shot | Few-shot |
|----------|-----------|----------|
| Стандартная задача (перевод, суммаризация) | ✅ | — |
| Специфический формат вывода | ❌ | ✅ |
| Новый домен (медицинские отчёты, юридические документы) | ❌ | ✅ |
| Тонкая стилистика | ❌ | ✅ |
| Сложный парсинг | ❌ | ✅ |

**Правило:** если zero-shot не работает — добавь 3 примера. Если не работает с 3 — добавь 5. Больше 5 — пересмотри подход.

---

## Chain-of-Thought (CoT)

Простая техника: добавь «давай подумаем пошагово».

```
❌ Без CoT:
"Сколько будет 24 * 37?"
→ "888" ❌ (может ошибиться)

✅ С CoT:
"Сколько будет 24 * 37? Давай подумаем пошагово."
→ "20 * 37 = 740, 4 * 37 = 148, 740 + 148 = 888" ✅
```

**Почему работает:** CoT даёт модели «место» для рассуждения. Вместо того чтобы угадывать ответ одним токеном, модель генерирует цепочку рассуждений, где каждый следующий токен опирается на предыдущий.

---

## Structured CoT (ReAct)

В агентах CoT превращается в структурированный формат:

```
Thought: Мне нужно найти файл с настройками БД.
В проекте обычно это config.py или settings.py.
Action: glob("**/config.py")
Observation: ["src/config.py", "src/settings.py"]

Thought: Нашёл два файла. Начну с config.py.
Action: read("src/config.py")
```

**Thought** — это CoT. **Action** — решение. **Observation** — факт.

Этот формат мы разобрали в [[01-fundamentals/03-react-pattern]].

## Few-shot + CoT = лучший результат

```python
def build_few_shot_cot(examples: list[dict], query: str) -> str:
    """Собирает промпт с примерами и CoT."""

    prompt = "Реши задачи. Для каждой распиши ход мыслей.\n\n"

    for i, example in enumerate(examples, 1):
        prompt += f"Задача {i}: {example['question']}\n"
        prompt += f"Рассуждение: {example['reasoning']}\n"
        prompt += f"Ответ: {example['answer']}\n\n"

    prompt += f"Задача: {query}\n"
    prompt += "Рассуждение:"

    return prompt


# Пример использования
EXAMPLES = [
    {
        "question": "Сколько будет 15 + 27?",
        "reasoning": "15 + 20 = 35, 35 + 7 = 42",
        "answer": "42"
    },
    {
        "question": "Сколько будет 100 - 33?",
        "reasoning": "100 - 30 = 70, 70 - 3 = 67",
        "answer": "67"
    },
]

prompt = build_few_shot_cot(EXAMPLES, "Сколько будет 48 + 25?")
# → LLM сгенерирует: "48 + 20 = 68, 68 + 5 = 73" → "73"
```

## Разбор реального few-shot — строка за строкой

Разберём промпт из [[assets/prompt-templates/README.md]] (шаблон №3):

```markdown
Извлеки данные из текста.

Формат ответа:
{
  "entities": [
    {"name": "<сущность>", "type": "person|org|location|date", "mentions": [start, end]}
  ]
}
```
**Строка 1:** `Извлеки данные из текста.` — императивная задача (не «помоги извлечь»)
**Строки 3-9:** `Формат ответа` — JSON-схема. Модель видит структуру заранее
**Поле `mentions`:** `[start, end]` — позиции символов в тексте. Модель должна вычислить их

```markdown
Примеры:

Текст: "Иван работает в Яндексе с 2020 года."
Ответ: {
  "entities": [
    {"name": "Иван", "type": "person", "mentions": [0, 4]},
    {"name": "Яндекс", "type": "org", "mentions": [16, 22]},
    {"name": "2020", "type": "date", "mentions": [28, 32]}
  ]
}
```
**Пример 1:** Модель видит: текст → правильный ответ. Учится вычислять `mentions`
**Индексы:** `[0, 4]` — «Иван» начинается на позиции 0, заканчивается на 4
**Три типа:** person, org, date — модель понимает, какие бывают типы

```markdown
Текст: "Вчера встреча с Ольгой в кафе на Тверской."
Ответ: {
  "entities": [
    {"name": "Вчера", "type": "date", "mentions": [0, 5]},
    {"name": "Ольга", "type": "person", "mentions": [18, 23]},
    {"name": "Тверская", "type": "location", "mentions": [32, 40]}
  ]
}
```
**Пример 2:** Другой текст, другой паттерн. Показывает, что тип `date` может быть не только числом, но и словом («Вчера»)
**Тип `location`:** раньше не встречался — модель видит, что перечень типов шире, чем в первом примере
**Важно:** 2 примера достаточно. Если дать 5 — модель начнёт «шуметь» (overfitting на примерах)

```markdown
---
Текст: "${user_input}"
Ответ:
```
**Разделитель `---`:** модель понимает: «новая задача, ответь так же, как в примерах»
**`${user_input}`:** будет заменён на реальный текст
**Правильный баланс:** 2 примера — для понимания формата. Дольше — модель переобучится на конкретные тексты

## Как выбрать количество few-shot примеров

```
Задача новая для модели?
  ├── Да → 3-5 примеров
  └── Нет
       │
       ▼
Формат сложный (> 5 полей)?
  ├── Да → 2-3 примера
  └── Нет
       │
       ▼
Формат стандартный (JSON, markdown)?
  ├── Да → 0-1 пример (zero-shot достаточно)
  └── Нет
       │
       ▼
Требуется точность?
  ├── Да → 2 примера + CoT
  └── Нет → 0 примеров (zero-shot быстрее)
```

## Когда CoT избыточен

| Задача | CoT | Без CoT |
|--------|-----|---------|
| Фактологический вопрос («столица Франции?») | Избыточно | ✅ |
| Простой перевод | Избыточно | ✅ |
| Арифметика | ✅ | ❌ |
| Логическое рассуждение | ✅ | ❌ |
| Генерация кода | Опционально | ✅ может быть быстрее |
| Креативное письмо | ❌ мешает | ✅ |

**Правило:** CoT для задач, где важен процесс. Без CoT — для задач, где важен только результат.

---

## Резюме

```
Zero-shot:  без примеров — для стандартных задач
Few-shot:   2-5 примеров — для специфических форматов
CoT:        «давай подумаем пошагово» — для рассуждений
Structured CoT: Thought → Action → Observation — для агентов

Комбинация: few-shot примеры + CoT рассуждение = лучший результат
```
