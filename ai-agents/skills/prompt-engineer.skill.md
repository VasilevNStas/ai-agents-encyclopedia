# Skill: Prompt Engineer

## Когда использовать
- Создание system prompt для агента
- Оптимизация существующего промпта
- Разработка промпта для конкретной задачи

## Шаблон промпта

```markdown
Role: <роль, которую играет LLM>
Context: <контекст, известные данные>
Task: <что нужно сделать>
Format: <формат ответа>
Constraints: <ограничения>
Examples: <примеры (опционально)>
```

## Чеклист качества

- [ ] Role определён? (кто ты, агент?)
- [ ] Context передан? (все нужные данные)
- [ ] Task сформулирован императивно? («сделай X», а не «пожалуйста, сделай X»)
- [ ] Format указан? (JSON, markdown, код)
- [ ] Constraints есть? (чего НЕ делать)
- [ ] Examples есть? (для сложных форматов)
- [ ] System prompt < 2000 токенов?
- [ ] Важное в начале и в конце?

## Правила

1. **Императивность:** «делай X», а не «пожалуйста, сделай X»
2. **Негативные инструкции:** «НЕ делай Y» работает хуже, чем «делай X вместо Y»
3. **Lost-in-the-middle:** важное — в начало и в конец промпта
4. **Temperature:** 0 для фактов, 0.7 для творчества
5. **Одна задача:** один промпт — одно действие

```python
})
```
