# Урок 1: Как работают LLM — ментальная модель

> [!quote] Ключевая идея
> LLM — это не «мозг» и не «база знаний». Это **машина для предсказания следующего токена**, которая в процессе этого предсказания вынуждена моделировать реальность.

---

## LLM — это engine предсказания

Самый важный факт, который нужно понять про LLM (Large Language Model):

> **LLM получает на вход последовательность токенов и предсказывает следующий токен.**

Всё. Это базовая операция. Всё остальное — рассуждения, планирование, творчество, «понимание» — **побочный эффект** того, что для точного предсказания следующего токена модель должна научиться моделировать причинно-следственные связи в тексте.

```python
# Упрощённая ментальная модель
def llm_next_token(context: list[int]) -> dict[int, float]:
    """Возвращает вероятности для каждого токена из словаря"""
    logits = model.forward(context)
    return softmax(logits)  # вероятности
```

### Аналогия от Карпати (Karpathy)

LLM — это **«симулятор документов» (document simulator)**. Представь, что у тебя есть нейронная сеть, которая обучалась на триллионах токенов из интернета. Она не «знает» факты — она умеет **продолжать паттерны**, которые видела в обучении.

Если ты начнёшь промпт с `«Вопрос: Какая столица Франции? Ответ:»`, модель продолжит паттерн «вопрос-ответ» и выдаст `«Париж»`. Не потому что она знает географию, а потому что в данных обучения за такой последовательностью чаще всего следует `«Париж»`.

---

## Токенизация — как LLM «читает» текст

LLM не видит буквы и слова. Она видит **токены** — числа, которые кодируют фрагменты текста.

```
"Привет, как дела?" → [1213, 456, 8910, 234]
```

- Токен может быть словом, частью слова или знаком препинания
- Размер словаря: 32k-200k токенов (зависит от модели)
- Разные языки кодируются по-разному (русский обычно требует больше токенов на слово, чем английский)

> [!warning] Почему это важно для агента
> Контекстное окно измеряется в **токенах**, а не в словах. Ограничение контекста — главный враг агентов. Планируй архитектуру так, чтобы не переполнять контекст.

---

## Attention — как LLM понимает контекст

Механизм **self-attention** (Vaswani et al., 2017) — секретный соус Transformer-архитектуры.

```
  Токен:  [Я] [люблю] [зелёный] [чай]
              \    |    /
              Attention
                 |
          [чай] предсказывает
          следующий токен
```

Attention позволяет каждому токену «смотреть» на все предыдущие токены в контексте и решать, какие из них важны для предсказания следующего.

> [!note] Интуиция
> Self-attention ≈ взвешенная сумма всех предыдущих токенов, где веса — это «важность» каждого токена для текущего.

**Проблема:** сложность attention — O(n²) по длине контекста. Это означает, что при удвоении контекста, вычислительная нагрузка растёт в 4 раза. Поэтому контекстные окна ограничены (даже 128k токенов — это компромисс).

## Sampling — как выбирается ответ

Модель выдаёт **вероятности** для всех токенов в словаре. Но как выбрать один?

```
Токен "чай":    0.45
Токен "кофе":   0.30
Токен "сок":    0.15
Токен "вода":   0.10
```

### Основные стратегии:

| Стратегия | Что делает | Когда использовать |
|-----------|-----------|-------------------|
| **Greedy** | Берёт токен с макс. вероятностью | Кодинг, фактологичные ответы |
| **Temperature** | "Сглаживает" распределение (T>1 = креативнее) | Творчество, генерация идей |
| **Top-k** | Выбирает из k самых вероятных | Баланс |
| **Top-p (nucleus)** | Выбирает из токенов, чья сумма вероятностей ≥ p | Современный стандарт |

```python
import torch

def sample_with_temperature(logits: torch.Tensor, temperature: float = 1.0):
    """Чем выше temperature, тем более «креативный» (хаотичный) ответ"""
    if temperature == 0:
        # Greedy
        return torch.argmax(logits)
    scaled = logits / temperature
    probs = torch.softmax(scaled, dim=-1)
    return torch.multinomial(probs, num_samples=1)
```

## Контекстное окно — оперативная память агента

**Context window = количество токенов, которое модель может «видеть» одновременно.**

| Модель | Размер контекста |
|--------|-----------------|
| GPT-4 (2023) | 8k — 32k |
| GPT-4 Turbo | 128k |
| Claude 3 Opus | 200k |
| DeepSeek-V2 | 128k |
| Gemini 1.5 Pro | 1M — 2M |

### Правило архитектора:

> **Контекст агента = Промпт + История диалога + Результаты вызовов инструментов**

Если твой агент вызывает много инструментов и хранит длинную историю — контекст закончится быстрее, чем ты думаешь.

**Стратегии экономии контекста:**
1. Обрезать историю (keep last N messages)
2. Суммаризировать историю (LLM пишет краткое резюме)
3. Выгружать во внешнюю память (RAG, Vector DB)
4. Использовать скользящее окно (Sliding Window Attention)

## Почему LLM «думает», хотя предсказывает токены — глубинная механика

Здесь кроется самый важный парадокс, который нужно понять архитектору:

> LLM предсказывает токены. Но чтобы **точно** предсказать следующий токен, модель должна **моделировать реальность**.

Пример: ты даёшь модели начало предложения «Иван взял зонт, потому что на улице...». Чтобы предсказать следующий токен, модель должна «понять»:
- Что идёт дождь (физика)
- Что зонт защищает от дождя (знание о мире)
- Что «дождь» — логичное продолжение (причинно-следственная связь)

Модель не «знает» физику. Но в её обучающих данных миллионы раз встречался паттерн «зонт → дождь». Этот паттерн настолько силён, что модель **вынуждена** научиться моделировать эту связь, чтобы предсказывать токены.

**Что это значит для архитектора:**

```
LLM не рассуждает как человек, но её предсказания выглядят как рассуждение.
Разница критична:
  - Человек думает → потом говорит
  - LLM говорит → это выглядит как думание

На практике разницы НЕТ — если нас интересует результат, а не процесс.
```

### Когда разница становится видна:

| Ситуация | Человек | LLM |
|----------|---------|-----|
| Знает ответ наверняка | Скажет «я уверен» | Скажет «я уверен» — даже если не прав |
| Не знает ответа | Скажет «не знаю» | **Сгенерирует правдоподобный ответ** (галлюцинация) |
| Считает 2+2 | «4» — всегда | «4» — почти всегда (вероятностно) |

### Вывод:

> Ты не можешь «убедить» LLM быть честной. Ты можешь только построить систему, которая **проверяет** её ответы. Все ограничения LLM компенсируются архитектурой: guardrails, инструментами, RAG, валидацией.

## Внутреннее устройство: от токена к смыслу

### Embedding — как модель «видит» слова

Каждый токен превращается в **вектор** — точку в многомерном пространстве (768-4096 координат):

```python
# Упрощённо: слова с похожим смыслом — рядом
embedding("король")  ≈ [0.2, 0.8, -0.3, ...]
embedding("монарх")  ≈ [0.2, 0.7, -0.3, ...]  # рядом с "король"
embedding("молоко")  ≈ [-0.5, 0.1, 0.9, ...]  # далеко от "король"
```

**Это и есть основа «понимания»:** модель не знает, что король и монарх — синонимы. Но их векторы находятся рядом в пространстве, потому что в данных обучения они встречались в похожих контекстах.

### Transformer — как токены «общаются»

```
Слой 1: каждый токен → embedding
Слой 2: self-attention → токены «смотрят» друг на друга
Слой 3: feed-forward → преобразование
...
Слой N: выход → вероятности следующего токена
```

Каждый слой Transformer — это шаг «размышления». 32-128 слоёв = 32-128 шагов «размышления» над контекстом.

### Почему context window ограничен

Self-attention имеет сложность **O(n²)** — токен «смотрит» на каждый предыдущий. На 1000 токенов — 1 млн связей. На 128 000 токенов — 16 млрд связей.

```
1000 токенов → 1M связей      → быстро
32 000 токенов → 1B связей     → заметно
128 000 токенов → 16B связей   → дорого
1 000 000 токенов → 1T связей  → очень дорого
```

Поэтому long context (1M+ токенов у Gemini) — это инженерный компромисс между качеством attention и скоростью.

## Ограничения LLM (критически важно для архитектора)

1. **LLM не думает.** Она предсказывает токены. Рассуждения (Chain of Thought) — это промптинг, а не архитектура мозга.
2. **LLM галлюцинирует.** Модель может выдать уверенный, но ложный ответ. Она не отличает «знание» от «правдоподобного продолжения».
3. **LLM не имеет памяти.** Каждый запрос — чистый лист (stateless). Вся «память» — это контекст, который ты передаёшь.
4. **LLM не считает.** Модель не умеет точно выполнять арифметику, если это не закодировано в инструменты.
5. **LLM не видит.** Она не «понимает» изображения в мультимодальном режиме — она преобразует их в токены и обрабатывает тем же механизмом.

## Резюме

```
LLM:
  Вход:  последовательность токенов
  Выход: вероятности следующего токена
  Механизм: self-attention (O(n²) по длине)
  Память:  контекстное окно (передаётся каждый раз)
  Ограничения: галлюцинации, stateless, не умеет считать
```

> [!important] Для архитектора
> LLM — это **движок**. Твоя задача как архитектора — построить вокруг этого движка систему, которая компенсирует его ограничения (память, инструменты, валидация) и усиливает его сильные стороны (генерация, рассуждение, переформулирование).
