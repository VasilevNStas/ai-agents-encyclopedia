# Урок 2: Что такое AI-агент? Анатомия агента

> [!quote] Определение
> **AI-агент** — это система, в которой LLM (Large Language Model) используется как **ядро принятия решений** (reasoning engine), обёрнутое в цикл: **наблюдай → думай → действуй → наблюдай результат**.

---

## Агент ≠ Чат

Главное различие между «чатом с LLM» и «агентом»:

| Характеристика | Чат | Агент |
|---------------|-----|-------|
| Управление | Пользователь ведёт | Агент ведёт сам |
| Инструменты | Нет | Есть (API, код, файлы, поиск) |
| Память | Только история чата | Структурированная (short/long-term) |
| Цикл | Один запрос → один ответ | Наблюдение → Мысль → Действие → ... |
| Автономность | Нулевая | Частичная или полная |

```python
# Чат: линейно
user_input → llm.generate() → output

# Агент: циклично
while task_not_complete:
    thought = llm.generate(observation, memory)
    action = parse_action(thought)
    observation = execute(action)
    memory.store(action, observation)
```

## Анатомия агента — 4 компонента

```
┌─────────────────────────────────────────┐
│               АГЕНТ                      │
│  ┌──────────┐  ┌──────────────────────┐  │
│  │   LLM    │  │     System Prompt    │  │
│  │  (ядро)  │  │  (личность, правила) │  │
│  └──────────┘  └──────────────────────┘  │
│  ┌──────────────────┐ ┌───────────────┐  │
│  │    Инструменты   │ │    Память     │  │
│  │ (Tools/Function  │ │ (Context +    │  │
│  │  Calling)        │ │  History)     │  │
│  └──────────────────┘ └───────────────┘  │
└─────────────────────────────────────────┘
```

### Компонент 1: LLM (Reasoning Engine)

Ядро агента. Не _просто_ генератор текста, а **движок рассуждений**.

Задачи LLM в агенте:
- Анализировать текущее состояние (observation)
- Принимать решение: что делать дальше?
- Форматировать ответ в структуру (JSON, код, вызов функции)
- Оценивать результат своих действий

> [!tip] Выбор модели
> Для агента критична **способность следовать инструкциям** (instruction following) и **поддерживать формат** (structured output). Не все модели одинаково хороши в этом. DeepSeek, Claude, GPT-4 — лучший выбор. Мелкие модели (7B-13B) пока плохо справляются с ролью агента.

### Компонент 2: System Prompt (Schema Layer)

Это «конституция» агента. Описывает:

```
Ты — ассистент по имени Алекс.
Правила:
1. Отвечай ТОЛЬКО в формате JSON
2. Если не уверен — скажи "не знаю"
3. Для поиска информации используй инструмент search()
4. Никогда не выдавай себя за другого человека
5. Если запрос опасный — откажись выполнять
```

> [!note] Это и есть Schema Layer (по Карпати)
> System prompt — это то, что превращает LLM из «болванки-предсказателя токенов» в дисциплинированного агента с характером и правилами. Эту тему мы разовьём в [[02-agent-patterns/03-tool-use]]

### Компонент 3: Инструменты (Tools / Function Calling)

Инструменты — это **мост** между LLM и внешним миром. Без них LLM — просто «говорящая голова», которая может только генерировать текст.

**Виды инструментов:**

| Тип | Примеры | Зачем |
|-----|---------|-------|
| Чтение | `read_file()`, `search_web()`, `query_db()` | Получить данные |
| Запись | `write_file()`, `send_email()`, `create_ticket()` | Изменить внешний мир |
| Вычисления | `calculate()`, `run_code()`, `chart()` | То, что LLM не умеет сама |
| Коммуникация | `ask_user()`, `notify()`, `escalate()` | Взаимодействие с людьми |

```python
# Как агент вызывает инструмент (function calling)
tools = [
    {
        "name": "search",
        "description": "Поиск информации в интернете",
        "parameters": {
            "query": {"type": "string", "description": "Поисковый запрос"}
        }
    }
]

# LLM решает: "Мне нужно узнать погоду → вызываю search()"
response = llm.generate(messages, tools=tools)
# response = {"function_call": {"name": "search", "args": {"query": "погода Москва"}}}
```

### Компонент 4: Память (Memory)

Подробно разберём в [[03-memory-and-rag/01-memory-types]], но кратко:

**Short-term memory** = контекстное окно (всё, что сейчас в промпте)

**Long-term memory** = то, что сохраняется между сессиями
- Файлы, векторные БД, графы знаний
- Форматы: Markdown-файлы (LLM Wiki), embeddings, knowledge graphs

**Working memory** = временные данные текущей задачи
- plan.md — план действий
- scratchpad — заметки агента «на полях»

## Цикл агента (Agent Loop)

Базовый цикл работы агента:

```
1. User Input (или триггер)
       ↓
2. LLM анализирует: состояние + контекст + инструменты
       ↓
3. LLM решает: ответить ИЛИ вызвать инструмент
       ↓
   ┌─── Если инструмент:
   │   4a. Выполнить инструмент → получить observation
   │   5a. Добавить observation в контекст
   │   6a. Вернуться к шагу 2
   │
   └─── Если ответ:
       4b. Вернуть ответ пользователю → конец
```

```python
def agent_loop(user_input: str, max_steps: int = 10):
    messages = [{"role": "user", "content": user_input}]
    
    for step in range(max_steps):
        response = llm.generate(messages, tools=AGENT_TOOLS)
        
        if response.has_tool_call():
            # Извлечь вызов инструмента
            tool_name = response.tool_call.name
            tool_args = response.tool_call.args
            
            # Выполнить
            result = execute_tool(tool_name, tool_args)
            
            # Добавить результат в контекст
            messages.append({
                "role": "tool",
                "content": str(result),
                "tool_call_id": response.tool_call.id
            })
        else:
            # Финальный ответ пользователю
            return response.content
    
    # Если достигли лимита шагов
    return "Agent terminated: max steps reached"
```

## Степени автономности

Не все агенты одинаково автономны. Это спектр:

```
Полный ручной ───────────────────── Полностью автономный
     │                                        │
     │                                        │
  Copilot                              Autopilot
 (человек решает,                  (агент решает,
  агент помогает)                   человек проверяет)
```

| Уровень | Название | Описание | Пример |
|---------|----------|----------|--------|
| 0 | Нет агента | LLM без инструментов | ChatGPT без плагинов |
| 1 | Copilot | Агент предлагает, человек утверждает | GitHub Copilot, OpenCode |
| 2 | Supervisor | Агент действует, человек наблюдает | Claude Code (execute mode) |
| 3 | Delegator | Агент действует, отчитывается о результате | Devin, автономные воркеры |
| 4 | Autopilot | Агент действует полностью сам | Trading bot, monitoring agent |

> [!warning] Для архитектора
> Уровень 3-4 требует **guardrails** (защитных рельсов). Без них агент может натворить дел. Тема [[05-production/01-guardrails]]

## Антипаттерны начинающих

1. **«Просто дадим LLM все инструменты»** — без чёткого промпта и ограничений агент будет дёргать инструменты хаотично, жечь токены и токены денег.
2. **«Агент сам разберётся»** — без чёткого плана (system prompt + структура) агент будет петлять. Мы обсудим это в [[02-agent-patterns/01-plan-and-solve]].
3. **«Один агент на всё»** — универсальный агент плох во всём. Лучше специализированные агенты + оркестратор (тема [[04-multi-agent/01-orchestration]]).

## Резюме

```
Агент = LLM (ядро) + System Prompt (конституция) + Инструменты (руки) + Память (архив)

Режим работы: цикл Observation → Thought → Action → Observation → ...
```

## Практическое задание

Попробуй в OpenCode или другом агентном CLI:

1. Напиши промпт без инструментов — просто попроси LLM выполнить задачу (например, «найди файлы, где упоминается database, и переименуй переменную»). Заметь, как она не сможет.
2. Добавь инструменты — дай агенту `grep`, `read`, `write` и попроси то же самое. Посмотри на разницу.

> [!tip] Это задание можно сделать прямо сейчас в этой сессии OpenCode. Просто попроси агента выполнить что-то, что требует инструментов.
