# Модуль 6: MCP — Model Context Protocol

> [!quote] Ключевая идея
> MCP — это USB-C для AI. Единый протокол, который позволяет
> LLM подключать любые инструменты, ресурсы и данные.

---

## 1. Архитектура

```
┌──────────┐    MCP    ┌──────────┐
│   Host   │◄────────► │  Server  │
│   (LLM)  │  stdio    │  (tools) │
└──────────┘   или     └──────────┘
               SSE
```

- **Host** — LLM (Claude, GPT, OpenCode)
- **Client** — протокольная прослойка (обычно встроена в host)
- **Server** — процесс, предоставляющий ресурсы, инструменты и промпты

---

## 2. Три примитива MCP

| Примитив | Описание | Аналог |
|----------|----------|--------|
| **Resources** | Данные, которые LLM может читать | GET endpoint |
| **Tools** | Действия, которые LLM может выполнять | POST endpoint |
| **Prompts** | Шаблоны промтов | Pre-built prompts |

### Resources (данные)

```json
{
  "uri": "file:///projects/myapp/README.md",
  "mimeType": "text/markdown",
  "content": "# My App\n..."
}
```

### Tools (действия)

```json
{
  "name": "search_code",
  "description": "Search codebase for a pattern",
  "inputSchema": {
    "type": "object",
    "properties": {
      "pattern": {"type": "string"},
      "path": {"type": "string"}
    }
  }
}
```

### Prompts (шаблоны)

```json
{
  "name": "code_review",
  "arguments": {
    "code": "string",
    "language": "string"
  },
  "template": "Проверь код на {{language}}: {{code}}"
}
```

## 3. Транспорт

### stdio (процесс)

Сервер запускается как подпроцесс. Общение через stdin/stdout.

```bash
npx @modelcontextprotocol/server-filesystem /path
```

Плюс: просто, безопасно (локально).
Минус: живёт только с host-процессом.

### SSE (сеть)

MCP-сервер работает как HTTP-сервер и отправляет события через Server-Sent Events. LLM-клиент подключается по URL и получает данные в реальном времени.

SSE — односторонний протокол поверх HTTP: сервер может отправлять данные клиенту без постоянных запросов. Встроенный механизм автоматически переподключается при обрыве связи.

```bash
npx @modelcontextprotocol/server-filesystem --sse --port 3000
```

Плюс: удалённый доступ, постоянная работа.
Минус: сложнее в настройке, безопасность.

## 4. Tool-use Prompting

Промт для работы с MCP-инструментами:

```
У тебя есть инструменты:
- search(query: str) — поиск по документации
- read_file(path: str) — чтение файла
- calculator(expression: str) — вычисления

Используй инструменты, когда тебе не хватает информации.
Не выдумывай факты — лучше вызови инструмент.
Если данные получены — ответь на их основе.
```

## 5. MCP vs Function Calling

| MCP | Function Calling |
|-----|-----------------|
| Стандарт | Проприетарный формат |
| Сервер — отдельный процесс | Функции — код в рантайме |
| Можно переиспользовать между LLM | Специфичен для провайдера |
| Сложнее в настройке | Проще |

**Когда что:** MCP — для production-систем с раздельными сервисами. Function Calling — для быстрых прототипов.

## 6. MCP в Production

### 6.1 Обработка ошибок

MCP-сервер может упасть — клиент должен быть готов:

```json
// Стандартный JSON-RPC error
{
  "jsonrpc": "2.0",
  "id": 1,
  "error": {
    "code": -32000,
    "message": "Tool execution failed",
    "data": { "tool": "search_code", "detail": "Index not found" }
  }
}
```

**Коды ошибок:** код < 0 — стандартные JSON-RPC, код > 0 — кастомные. Всегда обрабатывай timeout (рекомендуемый лимит: 30 сек на инструмент).

### 6.2 Безопасность

| Риск | Защита |
|------|--------|
| Сервер исполняет опасные команды | Запускай с минимальными правами (non-root), read-only где возможно |
| Утечка данных через Resources | Белый список путей, не используй `file:///` для всей файловой системы |
| DoS через дорогие инструменты | Rate limiting, лимит по токенам |
| Подмена MCP-сервера | Проверяй checksum сервера при установке |

### 6.3 Паттерны MCP-архитектуры

**Gateway-сервер:** один сервер, который маршрутизирует запросы к множеству backend-сервисов.

```
LLM → MCP Gateway → Internal API A
                  → Internal API B
                  → Database C
```

**Трансформер-сервер:** сервер принимает данные, преобразует, возвращает результат.

```
LLM → [Translate MCP] → перевод текста
LLM → [Format MCP] → markdown → HTML
```

**Caching-сервер:** кеширует результаты дорогих инструментов (search, композитные API).

### 6.4 MCP + Skills

MCP — протокол для подключения внешних инструментов. Skills — инструкции для агента. Комбинация:

```
Skill: "Когда нужно найти файл, используй MCP-сервер filesystem"
→ Агент читает skill, узнаёт про инструмент search_files
→ Агент вызывает search_files через MCP
→ Получает результат, формирует ответ
```

## 7. Ограничения MCP

- Нет встроенной аутентификации (решается на уровне транспорта — SSH-туннель, API-ключ)
- Нет потоковой передачи больших данных (пайпы не предусмотрены протоколом — для streaming нужен отдельный канал)
- Зависимость от рантайма сервера (Node.js для `@modelcontextprotocol/*`, Python для MCP Python SDK)
- Размер ответа ограничен памятью клиента
