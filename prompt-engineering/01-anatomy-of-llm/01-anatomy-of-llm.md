# Модуль 1: Анатомия LLM

> [!quote] Ключевая идея
> LLM — это не база знаний, а **симулятор документов**. Она не «знает» факты — она предсказывает, какие токены вероятнее всего должны идти следом.

---

## 1. Как работает генерация

### Токены

LLM не видит текст как буквы и слова. Она видит **токены** — кусочки текста.

```
"Привет, как дела?" → [Привет] [, ] [как] [ дела] [?]
```

- 1 токен ≈ 0.75 слова для английского, ≈ 1.5 символа для русского
- Ограничение контекста = ограничение по токенам (например, 128K токенов у GPT-4)
- Стоимость = цена за токен (input и output тарифицируются отдельно)

### Embedding

Каждый токен превращается в вектор — **embedding** — точку в многомерном пространстве (обычно 1024–4096 измерений).

```
# Упрощённо:
"король" → [0.2, -0.5, 0.8, ..., 0.1]   # 1024 числа
"королева" → [0.3, -0.4, 0.7, ..., 0.2]  # близкий вектор
"автомобиль" → [-0.8, 0.1, -0.3, ..., 0.6] # далёкий вектор
```

Семантическая близость = косинусная близость векторов.

### Attention

Механизм **attention** (внимание) определяет, какие токены в контексте важны для предсказания следующего токена.

```
На входе: "Кот сел на"

↓ attention взвешивает:
"Кот" → важно (кто?)
"сел" → важно (что сделал?)
"на"  → важно (предлог, нужен объект)

↓
Следующий токен: "коврик" (высокая вероятность)
```

### Probability Distribution

LLM выдаёт не один ответ, а **распределение вероятностей** для следующего токена:

```
"коврик"    → 0.45
"стул"      → 0.20
"диван"     → 0.15
"пол"       → 0.10
"крыша"     → 0.02
...         → ...
```

То, какой токен будет выбран, зависит от **temperature**.

## 2. Ключевые параметры

### Temperature (0.0 — 2.0)

Контролирует «креативность»:

| Temp | Эффект | Когда использовать |
|------|--------|-------------------|
| 0.0 | Всегда один и тот же ответ (greedy) | Факты, код, точные инструкции |
| 0.3–0.7 | Сбалансировано | Диалоги, ассистенты |
| 0.8–1.0 | Разнообразно | Творчество, генерация идей |
| > 1.0 | Хаотично | Эксперименты |

### Top-p (Nucleus Sampling, 0.0 — 1.0)

Вместо того чтобы брать фиксированное число кандидатов, top-p динамически выбирает минимальное множество самых вероятных токенов, чья суммарная вероятность достигает порога p.

```
top-p = 0.9:
токены с вероятностями 0.45 + 0.20 + 0.15 + 0.10 = 0.90
→ кандидаты: "коврик", "стул", "диван", "пол"
→ "крыша" (0.02) отсекается
```

| p | Эффект | Когда |
|---|--------|-------|
| 0.1–0.3 | Консервативно, почти детерминированно | Факты, точность |
| 0.9–0.95 | Сбалансированно | Стандартный режим |
| 1.0 | Все токены — кандидаты | Максимальное разнообразие |

### Top-k (1 — N)

Оставляет ровно k самых вероятных токенов, остальным даёт вероятность 0.

```
top-k = 3: "коврик", "стул", "диван" — только они могут быть выбраны
```

| k | Эффект |
|---|--------|
| 1 | Жадный поиск (greedy) — всегда самый вероятный токен |
| 10–40 | Стандартный диапазон для генерации |
| 50+ | Высокая креативность, риск нелогичности |

**На практике:** обычно используют top-p, а не top-k. Top-k полезен, когда нужно жёстко ограничить набор возможных вариантов.

### Max Tokens

Максимальная длина ответа. Важно для:
- Контроля стоимости (каждый токен — деньги)
- Предсказуемости (обрывается на середине мысли, если лимит мал)
- UX (не дать LLM «разговориться»)

## 4. Архитектура Transformer

Современные LLM (GPT-4, Claude, Llama) построены на архитектуре **decoder-only Transformer** — это ответ на вопрос №2.

### Decoder-only

Оригинальный Transformer (2017) состоял из encoder и decoder. LLM используют только decoder с **causal attention**: каждый токен «видит» лишь предыдущие.

### Ключевые компоненты

| Компонент | Роль |
|-----------|------|
| Multi-Head Attention | Взвешивает важность токенов |
| Feed-Forward (FFN) | Нелинейное «осмысление» контекста |
| Layer Normalization | Стабилизирует числовые значения |

### Путь токена

```
Токены → Embedding → [Attention → Norm → FFN → Norm] × N → Логиты → Вероятности
```

N слоёв последовательно уточняют представление токенов.

### Связь слоёв и размера модели

Число слоёв определяет объём параметров:

| Модель | Параметры | Слоёв |
|--------|-----------|-------|
| Llama 3.1 8B | 8B | 32 |
| Llama 3.1 70B | 70B | 80 |
| GPT-4 | ~1.8T | ~120 |

### Почему decoder-only

1. **Эффективность:** без encoder меньше вычислений
2. **Масштабируемость:** работает при триллионах параметров
3. **In-context learning:** обучение на контексте без дообучения

## 5. Ментальная модель: LLM — симулятор документов

> [!warning] Важнейшее понимание
> LLM **не хранит факты**. Она не знает, что «столица Франции — Париж». Она предсказывает, что в документах, которые она видела в обучении, после фразы «Столица Франции —» чаще всего идёт «Париж».

### Почему это важно

```
LLM не рассуждает — она имитирует:

вопрос = "Сколько сейчас времени?"
→ В обучающих данных нет документов про «сейчас» —
  LLM не может ответить (timestamp не зафиксирован)

вопрос = "Какая столица Франции?"
→ В обучающих данных миллионы документов про Париж —
  LLM уверенно отвечает «Париж»
```

### Почему LLM «галлюцинирует»

1. **Смешение документов:** Встречала «Эйфелева башня в Париже» и «Эйфелева башня в Лас-Вегасе» → может сказать, что «Эйфелева башня в Риме» (смешала контексты)
2. **Редкие факты:** Если факт встречается редко, вероятность правильного ответа падает
3. **Давление авторитета:** LLM запрограммирована быть полезной — лучше придумает, чем скажет «не знаю»

### Это нормально

Галлюцинации — не баг, а **фича** симулятора. LLM хороша ровно в том, в чём хороша: генерация правдоподобного текста. Наша задача как инженеров — строить системы, которые компенсируют эту особенность (RAG, инструменты, верификация).

## Практика: Игра с параметрами

> [!tip] Задание
> Возьми любой LLM-клиент (ChatGPT, Claude, OpenCode) и выполни эксперименты ниже. Записывай наблюдения.

### Эксперимент 1: Temperature

**Промт:** «Напиши короткое стихотворение про нейросети»

Попробуй:
- temperature = 0.0 (3 раза — должен быть одинаковый результат)
- temperature = 0.5 (умеренные вариации)
- temperature = 1.0 (каждый раз уникально)
- temperature = 1.5 (почти бессвязно)

**Вопросы для самоанализа:**
- Насколько отличаются результаты?
- Какой temperature дал самый «скучный» результат? Самый интересный?
- Где граница, после которой текст теряет смысл?

### Эксперимент 2: Симулятор документов

**Промт:** «Расскажи подробно о городе Ньюпорт-Бич. Если не знаешь — скажи "я не знаю"»

**Наблюдения:**
- LLM скорее всего уверенно расскажет про Ньюпорт-Бич (CA) — правдоподобно, но возможно с ошибками
- Почему? Потому что в обучающих данных этот город упоминается
- Сравни с реальными фактами через поиск в Google

**Вопросы для самоанализа:**
- Какие детали показались подозрительными?
- Как отличить уверенный ответ от правильного?

### Эксперимент 3: Параметры в действии

**Промт:** «Объясни квантовые вычисления ребёнку 7 лет»

Попробуй комбинации:
- temp=0.0, top-p=0.1, max_tokens=50
- temp=0.7, top-p=0.9, max_tokens=500
- temp=1.2, top-p=0.95, max_tokens=200

**Вопросы для самоанализа:**
- Как max_tokens влияет на полноту ответа?
- Какая комбинация дала лучшее объяснение для ребёнка?
- Что произошло при temp=0.0 top-p=0.1?
