# Модуль 4: ReAct & Агенты

> [!quote] Ключевая идея
> LLM перестаёт быть «болталкой» и получает руки — может вызывать
> инструменты, анализировать результат и действовать.

---

## 1. Паттерн ReAct

**Reasoning + Acting** — цикл из 4 шагов:

```
Thought:  Мне нужно узнать погоду в Москве. У меня есть инструмент weather.
Action:   weather("Москва")
Observation: "{temp: 15, condition: cloudy}"
Thought:  Температура 15 градусов, облачно. Формирую ответ.
Answer:   В Москве сейчас 15°C, облачно.
```

### Без ReAct:

```
User:  Какая погода в Москве?
LLM:   Извините, я не знаю — мои данные закончились в мае 2025.
```

### С ReAct:

```
User:  Какая погода в Москве?  
LLM:   [Thought: Нужно вызвать weather] 
       [Action: weather("Москва")]
       [Observation: 15°C, облачно]
       Сейчас в Москве 15°C и облачно.
```

## 2. Function Calling

Как LLM «объявляет» вызов инструмента:

```json
{
  "function": "get_weather",
  "parameters": {"city": "Москва"}
}
```

Рантайм перехватывает этот JSON, исполняет функцию и возвращает результат.

### Промт для function calling

```
Ты — ассистент с инструментами.

Инструменты:
- get_weather(city: str) → {"temp": int, "condition": str}
- search(query: str) → [{"title": str, "url": str}]

Когда тебе не хватает информации — вызови инструмент.
Если данных достаточно — ответь.

НЕ выдумывай факты, которые можно получить через инструменты.
```

---

## 3. Agent Loop

Полный жизненный цикл агента:

```
1. Вход: пользовательский запрос
2. Планирование: LLM решает, какие шаги нужны
3. Исполнение:
   ┌─> Thought → Action → Observation ─┐
   └────────────────────────────────────┘
   (повторяется, пока не накоплена информация)
4. Рефлексия: LLM проверяет, достаточно ли данных
5. Ответ: формирование финального ответа
```

### Типы агентов

| Тип | Описание | Когда |
|-----|----------|-------|
| **Single-step** | Один вызов инструмента, потом ответ | Простые вопросы (погода, курс валют) |
| **Multi-step** | Цепочка вызовов | Сложные вопросы (сравнение цен + поиск отзывов) |
| **Conversational** | Агент с памятью о диалоге | Чат-боты, поддержка |

## 4. Обработка ошибок в цикле агента

Агент не всегда получает идеальный результат с первого раза.

### Ошибка инструмента

Инструмент может вернуть ошибку, а не данные.

```
Thought: Нужно узнать погоду в Москве.
Action:   get_weather("Москва")
Observation: ERROR: API timeout

→ Варианты поведения:
  1. Повторить (retry) — если ошибка временная
  2. Выбрать другой инструмент — если есть альтернатива
  3. Сообщить пользователю — если данные недоступны
```

### Неполные данные

Инструмент вернул данные, но их недостаточно для ответа.

```
Thought: Нужно узнать курс доллара.
Action:   get_exchange_rate("USD")
Observation: {"rate": 92.5}
Thought: Данные есть, но это курс ЦБ. Нужен ещё курс продажи в банках.
Action:   search("курс доллара в банках москвы")
...
```

### Стратегии повторных попыток

| Стратегия | Описание | Когда |
|-----------|----------|-------|
| **Immediate retry** | Попробовать ещё раз сразу | Таймаут сети |
| **Backoff** | Ждать 1с → 2с → 4с перед повтором | Перегрузка API |
| **Alternative tool** | Использовать другой инструмент | Инструмент недоступен |
| **Fallback** | Сказать пользователю, что данные недоступны | Все источники исчерпаны |

## 5. Multi-step планирование

Сложные задачи требуют последовательности вызовов. Промт для multi-step агента:

```
Ты — аналитический агент. У тебя есть инструменты:
- search(query) — поиск
- calculator(expr) — вычисления
- save_note(key, value) — сохранение

Перед началом составь план действий.
Для каждого шага определи, какой инструмент нужен.
Если шаг не требует инструмента — используй свою базу знаний.
После получения всех данных — сформируй ответ.
```

### Пример multi-step: Сравнение товаров

```
User: Какой iPhone выгоднее купить — 15 Pro или 16?

Thought: Нужно сравнить цены на обе модели.
План:
1. search("iPhone 15 Pro цена") → цена модели А
2. search("iPhone 16 цена") → цена модели Б
3. calculator("цена_А - цена_Б") → разница
4. Ответ: сравнение с цифрами

Action: search("iPhone 15 Pro цена магазины")
Observation: "iPhone 15 Pro 256GB — 89990₽"
...
```

## 6. Эскалация

Агент должен знать, когда он не справляется, и передать задачу.

```
Thought: Запрос пользователя требует доступа к личным данным.
У меня нет инструментов для авторизации.
→ Эскалация: "Для обработки этого запроса нужен доступ к вашему аккаунту.
Пожалуйста, обратитесь в поддержку."
```

**Правило:** Эскалация — не ошибка. Это правильное поведение агента, который знает свои границы.

## 7. Timeout

Агент не должен думать бесконечно.

- **Максимум шагов:** ограничь количество итераций цикла (обычно 5-10)
- **Максимум времени:** если агент не уложился — ответ с тем, что есть
- **Защита от петель:** если Thought → Action → Observation повторяется без прогресса — остановись

```
Ты — агент. Твои ограничения:
- Максимум 5 вызовов инструментов за один запрос
- Если после 3 вызовов нет прогресса — ответь с тем, что есть
- Если один и тот же инструмент вызывается 2 раза подряд — остановись и сообщи об ошибке
```

## 8. Практика: Агент с обработкой ошибок

> [!tip] Задание
> Спроектируй агента с 3 инструментами для сбора информации.

**Инструменты:**
- `search(query)` — поиск в интернете
- `calculator(expression)` — вычисления
- `memory_save(key, value)` — сохранить факт

**Задача:** «Сколько будет 15% от 840? Сравни с курсом доллара на сегодня и сохрани результат.»

**Твой агент должен:**
1. Вызвать calculator для 15% от 840
2. Вызвать search для курса доллара
3. Вызвать memory_save для результата
4. Ответить пользователю
