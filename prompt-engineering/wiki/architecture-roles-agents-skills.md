# Архитектура ролей: AGENTS.md vs Skills

> Аналогия с ООП для понимания того, как устроены
> роли в промт-системах.

---

## Модель

```
AGENTS.md      = КОНСТРУКТОР профессора
skill("code-review") = MIXIN / временное переключение режима
```

## ООП-аналогия

### AGENTS.md — это конструктор класса

```python
class Professor:
    """Базовое поведение: роль, тон, методика, wiki-менеджмент."""

    def отвечать_на_вопрос(self, вопрос):
        """Сократовский метод: вопрос → ответ → уточнение."""

    def задать_вопрос(self, тема):
        """Проверка понимания."""

    def создать_wiki(self, страница):
        """После обсуждения зафиксировать в /wiki/."""
```

### skill — это mixin / интерфейс

```python
class CodeReviewer:
    """Временное поведение: role=reviewer, format=JSON, guardrails."""

    def review(self, code):
        """Проверить код, вернуть JSON с issues."""
```

Профессор временно реализует интерфейс `CodeReviewer`, но остаётся профессором.

---

## Как это работает в сессии

```
=== НАЧАЛО СЕССИИ ===
AGENTS.md: профессор
→ отвечает с вопросами
→ использует сократовский метод

=== ПЕРЕКЛЮЧЕНИЕ ===
Студент: "skill("code-review")"
Профессор читает code-review.skill.md
→ временно меняет правила
→ теперь role=reviewer, format=JSON

=== РЕЖИМ REVIEWER ===
Студент: "Проверь код"
Профессор (в режиме reviewer): {"issues": [...]}

=== ВОЗВРАТ ===
Студент: "Продолжим урок"
Профессор: "Хорошо. Какой модуль дальше?"
→ снова профессор, сократовский метод
```

---

## Свойства модели

| Свойство | AGENTS.md | skill("...") |
|----------|-----------|-------------|
| Персона | Профессор | Любая (reviewer, analyst, tutor) |
| Правила | Фундаментальные (тон, метод) | Узкие (формат, guardrails) |
| Длительность | Вся сессия | До следующего возврата |
| Кто пишет | Разработчик курса | Разработчик курса или студент |
| Переопределение | Никогда | Временно, на одну задачу |
| Возврат | — | Автоматически после задачи |

---

## Почему это важно понимать

1. **AGENTS.md не нужно менять** под каждую новую задачу — это конструктор, а не свалка ролей
2. **Skills — это переиспользуемые кирпичи.** Один skill("code-review") можно вызвать в любом проекте
3. **Чистота ролей.** Профессор не должен уметь проверять код «из коробки» — это отдельная компетенция
4. **Масштабирование.** Нужен новый режим → создаёшь новый `.skill.md`, не трогая AGENTS.md
