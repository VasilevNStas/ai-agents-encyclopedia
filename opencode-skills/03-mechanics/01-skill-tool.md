# Skill Tool — как работает под капотом

**Время чтения:** 7 мин

## Суть

Skill Tool — механизм, который связывает описание задачи пользователя с SKILL.md из установленных пакетов. Когда агент вызывает `skill("name")`, система сканирует все доступные директории, находит skill по имени и загружает его содержимое в контекст сессии.

## Основной материал

### Процесс загрузки skill

Когда пользователь даёт задачу, агент проходит следующую цепочку:

1. **Задача** — пользователь пишет запрос (например, "напиши тесты")
2. **Сканирование метаданных** — агент просматривает name + description всех зарегистрированных skills
3. **Match description** — description каждого skill сравнивается с текущей задачей (семантическое сходство)
4. **Активация** — если match проходит (порог 1%), вызывается Skill Tool, который читает полный SKILL.md
5. **Интеграция** — содержимое SKILL.md добавляется в system prompt агента поверх базовых инструкций
6. **Выполнение** — агент следует инструкциям, при необходимости подгружает файлы из scripts/, references/

### Progressive disclosure на практике

```
При старте сессии:
  → Агент читает ТОЛЬКО name + description всех skills
  → Это ~100 токенов на skill, даже если skills сотни

При совпадении задачи с description:
  → Агент загружает полный SKILL.md
  → Рекомендуемый размер: < 5000 токенов

При необходимости:
  → Агент подгружает scripts/, references/, assets/
  → Только те файлы, которые реально нужны для задачи
```

Это означает, что агент на этапе оценки решения опирается **только на name и description**, не зная полного содержания skill.

### Формат вызова в разных CLI

| CLI | Инструмент | Пример |
|-----|-----------|--------|
| OpenCode | `skill` | `skill("writing-plans")` |
| Claude Code | `Skill` | `Skill("writing-plans")` |
| Gemini CLI | `activate_skill` | `activate_skill("writing-plans")` |
| GitHub Copilot | `skill` | `skill("writing-plans")` |

Несмотря на разные имена, все делают одно и то же: находят SKILL.md, читают его, возвращают содержимое агенту.

### Ограничения

- **Размер SKILL.md:** большие файлы (10K+ токенов) съедают контекст. Рекомендуется держать skills компактными (2-3K токенов максимум)
- **Skill не может загрузить другой skill напрямую.** Только агент решает, какие skills загружать
- **Количество одновременно загруженных:** нет жёсткого лимита, но каждый skill потребляет токены. Официальная рекомендация: не превышать 20-50 активных skills, иначе снижается качество триггеринга
- **SUBAGENT-STOP:** некоторые skills содержат инструкцию, запрещающую subagent'ам их загружать

### Когда skill НЕ применяется

- **Не прошёл match** — описание не совпало с задачей (агент оценил вероятность ниже 1%)
- **Skill не найден** — нет директории с таким name
- **Пользователь явно запретил** — AGENTS.md говорит "don't use X"
- **Слишком простая задача** — агент может обработать её без skill (одношаговые запросы вроде "прочитай этот PDF" часто не триггерят skills)

### Автотриггеринг

Главная особенность skills: агент сам решает, когда их применить. Это называется автотриггеринг. Хорошо написанный skill триггерится на 90% релевантных запросов без явного вызова — это официальная метрика Anthropic.

## Кейс

Пользователь пишет: "у меня баг в функции рендеринга". Агент анализирует, видит skill `systematic-debugging` с description "Use when encountering any bug, test failure, or unexpected behavior, before proposing fixes". Проверяет: есть ли совпадение >= 1%? Да. Вызывает `skill("systematic-debugging")`. Система находит SKILL.md в установленных пакетах, читает его и возвращает агенту. Агент добавляет инструкции в контекст и выполняет чеклист.

## Упражнение

Представь, что ты агент. Пользователь сказал: "напиши тесты". Опиши последовательность шагов от получения запроса до завершения тестов — с указанием, на каком шаге и какой skill загружается.

## Проверь себя

1. Опишите цепочку шагов от задачи пользователя до выполнения skill.
2. Какие данные читаются на этапе сканирования метаданных?
3. Может ли skill загрузить другой skill напрямую?
4. Назовите хотя бы две причины, по которым skill может не примениться.
5. Какой процент релевантных запросов должен триггерить хорошо написанный skill (по метрике Anthropic)?

## Ключевые выводы

- Skill Tool — мост между задачей пользователя и SKILL.md
- Progressive disclosure: метаданные → инструкции → ресурсы
- Description — единственное, на что опирается агент на этапе оценки
- Skill дополняет system prompt, а не заменяет его
- Каждый CLI использует своё имя инструмента, но логика одинаковая
