# Best practices для написания skills

**Время чтения:** 15 мин

## Суть

Хороший skill — конкретный, проверяемый, переиспользуемый набор инструкций, который агент загружает по триггеру и выполняет без лишних вопросов. Плохой skill — источник путаницы, ложных срабатываний и пустой траты токенов.

## Основной материал

### Принципы хорошего skill

**Начинай с реальной задачи.** Лучший способ создать хороший skill — выполнить реальную задачу с агентом, зафиксировать свои коррекции, и извлечь повторяющийся паттерн. Skill, рождённый из реального опыта, всегда лучше сгенерированного из общих знаний.

Полезные источники для синтеза skill:
- Внутренняя документация, runbooks, style guides
- API-спецификации и конфигурационные файлы
- Комментарии к код-ревью (отражают повторяющиеся проблемы)
- История изменений в git (патчи и фиксы)
- Реальные кейсы отказов и их решения

**Экономь контекст.** Каждый токен в твоём skill конкурирует за внимание агента со всем остальным в контекстном окне.

- Пиши только то, чего агент **не знает без твоего skill**
- Не объясняй очевидное (что такое PDF, как работает HTTP)
- Одно отличное пример лучше трёх посредственных

**Калибруй контроль.** Не каждая часть skill требует одинаковой жёсткости:

- **Свобода** — когда допустимы разные подходы. Объясняй WHY, а не WHAT
- **Prescriptive** — когда порядок действий критичен. Пропиши команды дословно

**Давай умолчания, а не меню.** Выбирай один подход по умолчанию, альтернативы упоминай кратко:

```markdown
# ✅ Правильно: чёткий дефолт
Use pdfplumber for text extraction:
  import pdfplumber
For scanned PDFs requiring OCR, use pdf2image + pytesseract.

# ❌ Неправильно: меню без дефолта
You can use pypdf, pdfplumber, PyMuPDF, or pdf2image...
```

**Процедуры, а не ответы.** Skill должен учить подходу, а не давать ответ для одного случая:

```markdown
# ❌ Ответ для одного случая
Join orders to customers on customer_id, filter region='EMEA', sum amount.

# ✅ Метод для всех случаев
1. Read schema from references/schema.yaml to find relevant tables
2. Join tables using _id foreign key convention
3. Apply filters from user's request as WHERE clauses
```

### Паттерны эффективных инструкций

**Gotchas — список неочевидных подводных камней.** Это самое ценное, что может быть в skill. Конкретные факты, которые агент не узнает без инструкции:

```markdown
## Gotchas

- The `users` table uses soft deletes. Queries must include
  `WHERE deleted_at IS NULL`.
- User ID is `user_id` in DB, `uid` in auth service, and
  `accountId` in billing API — all refer to the same value.
```

**Templates — шаблоны вывода.** Агенты лучше работают с конкретными структурами, чем с описанием формата в прозе:

```markdown
## Report structure

Use this template:
# [Title]
## Executive summary
...
```

**Checklists для многошаговых процессов.** Помогают агенту не пропускать шаги:

```markdown
## Form processing workflow

- [ ] Step 1: Analyze the form
- [ ] Step 2: Validate mapping
- [ ] Step 3: Fill the form
```

**Validation loops.** Инструктируй агента проверять свою работу:

```markdown
1. Make edits
2. Run validation: python scripts/validate.py
3. If validation fails — fix and re-run
4. Only proceed when validation passes
```

**Plan-validate-execute.** Для опасных операций (batch, destructive) — создай промежуточный план, проверь, только потом выполняй.

### DO

- Конкретные description — описывай точный триггер, а не общую тему
- Gotchas-секции — список того, что сломается без инструкции
- Проверяемые шаги — чеклисты, валидация
- Примеры кода — показывай ожидаемый формат ввода/вывода
- Умолчания — выбирай один подход, альтернативы — кратко
- Процедуры — учи методу, а не давай ответ

### DON'T

- Длинные файлы: skill > 500 строк / 5000 токенов — разбивай на reference-файлы
- Неявные зависимости: если skill требует установки пакета — укажи явно
- Противоречия AGENTS.md: skill не должен отменять правила из AGENTS.md
- Пустые триггеры: description без конкретики → ложные срабатывания
- Narrative-примеры: "в сессии 2025-10-03 мы нашли баг..." — слишком частно
- Multi-language: один отличный пример на одном языке, а не три посредственных на разных

### Антипаттерны

**"Всё в одном"** — один skill на все задачи:
```yaml
name: helper
description: Helps with various tasks
```

**"Слепое копирование"** — скопировал skill, не поменял description:
```yaml
name: commit-checker
description: Format JSON data with proper indentation  # ❌
```

**"Молчаливый skill"** — есть название, нет инструкций:
```yaml
name: code-reviewer
description: Review code changes before merge
# Пусто — агент действует по умолчанию
```

### Checklist для production-готовности

- [ ] Description уникален и описывает только условия триггера (не workflow)
- [ ] Инструкции покрывают все шаги от начала до конца
- [ ] Gotchas-секция содержит неочевидные подводные камни
- [ ] Примеры показывают ожидаемый формат
- [ ] Нет противоречий с AGENTS.md
- [ ] Skill протестирован на реальной задаче
- [ ] Нет неявных зависимостей
- [ ] Файл не превышает ~500 строк

### Рефакторинг skills

**Split** — если skill делает две независимые вещи, раздели на два:
- `code-reviewer` и `deployment-checker` вместо `review-and-deploy`

**Merge** — если два skills всегда загружаются вместе, объедини:
- `commit-formatter` + `commit-message-validator` → `commit-assistant`

**Rename** — если description не совпадает с реальным применением

### Когда skill слишком мал

1-2 строки инструкций — вероятно, это должно быть в `AGENTS.md`, а не в отдельном skill. Skill оправдан, когда:
- Инструкций больше 5 строк
- Есть gotchas или hard-to-know факты
- Требуются скрипты или референсы
- Skill被 используется в нескольких проектах

## Проверь себя

1. Какой принцип лежит в основе создания хорошего skill?
2. Что такое Gotchas-секция и почему она считается самым ценным элементом skill?
3. Назовите четыре антипаттерна написания skills.
4. В каких случаях skill оправдан, а когда лучше использовать AGENTS.md?
5. Что такое рефакторинг split и merge применительно к skills?

## Ключевые выводы

- Начинай с реальной задачи, а не с теории
- Экономь контекст: пиши только то, чего агент не знает
- Gotchas — самое ценное, что может быть в skill
- Description описывает триггер, НЕ workflow
- 4 антипаттерна: "Всё в одном", "Слепое копирование", "Молчаливый skill", "Неявные зависимости"
- Рефакторинг: split, merge, rename
