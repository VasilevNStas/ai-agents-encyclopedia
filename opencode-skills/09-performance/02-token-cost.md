# Token Cost

**Время чтения:** 5 мин

## Суть

Каждый загруженный skill занимает место в контекстном окне. Надо понимать, сколько токенов стоит skill, и решать, оправдана ли эта цена пользой, которую он приносит.

## Основной материал

### Как считать токены

Точный подсчёт зависит от токенизатора модели, но приблизительно:

- **Английский:** 1 токен ≈ 0.75 слова
- **Русский:** 1 токен ≈ 0.6 слова (из-за морфологии)

Формула: `token_count = word_count / words_per_token`

### Token-кост типичных skills

| Skill | Слов | Токенов | Процент при загрузке (из 100K) |
|-------|------|---------|-------------------------------|
| brainstorming | 400 | 530 | 0.5% |
| systematic-debugging | 350 | 470 | 0.5% |
| subagent-driven-dev | 600 | 800 | 0.8% |
| writing-plans | 500 | 670 | 0.7% |

**Кумулятивный эффект:**
- 1 skill: 0.5-1%
- 4 skills: 2-4%
- 8 skills: 4-8%
- 15 skills (перегрузка): 8-15%

### Trade-off: когда skill стоит токенов

Skill оправдан, если:
- **Без него агент делает ошибки** — тогда skill экономит токены на исправлениях
- **Задача сложная** — skill даёт структуру, чеклисты, gotchas
- **Skill используется часто** — затраты на загрузку амортизируются

Skill НЕ оправдан, если:
- Задача тривиальна: "переименуй переменную"
- Skill большой, а нужна лишь малая часть
- Контекстное окно почти заполнено
- Без skill агент справляется так же хорошо

### Метрика: token ROI

Оценка окупаемости токенов:

```
ROI = (pass_rate_with_skill - pass_rate_without) / token_cost

Пример:
pass_rate_with = 0.83
pass_rate_without = 0.33
token_cost = 500

ROI = (0.83 - 0.33) / 500 = 0.001

Сравнивай ROI разных skills для принятия решения.
```

### Оптимизация token-коста

**1. Удали воду из SKILL.md**

Каждый токен должен работать. Если предложение можно удалить без потери смысла — удали.

```markdown
# ❌ Вода
Before we begin, it's important to note that you should always
check the documentation first.

# ✅ Только суть
Check docs/spec.md before implementation.
```

**2. Используй кросс-ссылки вместо дублирования**

```markdown
# ❌ Повторяет инструкции из другого skill
1. Run tests: pytest tests/
2. Check coverage: pytest --cov
3. Format code: black .

# ✅ Ссылается
Follow the testing workflow from code-testing skill.
```

**3. Выноси таблицы и списки в reference**

Если в SKILL.md есть таблица на 50 строк — вынеси её в `references/` и дай указание загружать по необходимости.

**4. Оптимизируй description**

Description не должен быть длиннее 1024 символов (лимит спецификации). Но и слишком короткий не поможет — агент не поймёт, когда загружать.

## Кейс / пример

У пользователя 100K контекста. Загружено 4 навыка (brainstorming, TDD, debugging, code-review). Каждый ~2500 токенов. Итого 10K токенов (10%) уходит только на skills.

Оптимизация:
- Brainstorming нужен только в начале проекта → не держать в контексте постоянно
- Объединить TDD + code-review в один workflow-skill
- Вынести детали debugging в reference

После оптимизации: 2 skills, ~3000 токенов (3% окна).

## Упражнение

## Ключевые выводы

- 1 skill занимает 0.5-1% контекстного окна (100K)
- SKILL.md рекомендуется держать до 500 слов / 5000 токенов
- Token ROI = (польза от skill) / (token cost)
- Оптимизация: удаляй воду, используй кросс-ссылки, выноси детали в reference
- Skill оправдан, если без него агент делает ошибки
