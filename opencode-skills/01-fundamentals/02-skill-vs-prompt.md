# Skill vs System Prompt vs AGENTS.md

**Время чтения:** 7 мин

## Суть

System Prompt, AGENTS.md (CLAUDE.md, GEMINI.md) и Skill — три уровня инструкций для AI-агента. Они различаются областью действия, персистентностью и приоритетом. Понимание иерархии необходимо, чтобы предсказывать поведение агента в конфликтных ситуациях.

## Основной материал

### System Prompt

Задаётся платформой (Claude Code, Copilot CLI, Gemini CLI). Действует всегда, на каждую сессию. Пользователь обычно не может его изменить (если только через конфигурацию платформы).

Содержит: базовые правила поведения, формат ответов, доступные инструменты.

### AGENTS.md / CLAUDE.md / GEMINI.md

Проектные инструкции, которые агент читает в начале каждой сессии. Всегда в контексте. Определяют правила работы над конкретным проектом.

Содержат: настройки диалогов, требования к стилю кода, команды для сборки/тестов, ссылки на документацию.

Если инструкций мало (1-2 строки) — их место здесь, а не в отдельном skill.

### Skill

Загружается только когда задача совпадает с description. Живёт в отдельной директории, не засоряет контекст. Может быть установлен из пакета или лежать локально.

Содержит: YAML frontmatter (name, description), пошаговые инструкции, чеклисты, скрипты, референсы.

### Иерархия приоритетов

```
1. AGENTS.md / CLAUDE.md / GEMINI.md — высший приоритет
2. Skill — средний приоритет (сортируются по релевантности)
3. System Prompt — базовый, низший приоритет
```

Пример конфликта:

- **AGENTS.md:** "Никогда не используй npm, только yarn"
- **Skill "package-manager":** "Используй npm для установки зависимостей"

→ Побеждает AGENTS.md, потому что проектные инструкции выше skill.

### Когда что использовать

| Критерий | System Prompt | AGENTS.md | Skill |
|----------|--------------|-----------|-------|
| Область | Платформа | Проект | Конкретная задача |
| Персистентность | Всегда | Вся сессия | По необходимости |
| Кто пишет | Платформа | Пользователь | Разработчик skill |
| Объём | Задано платформой | 1-20 строк | 50-500 строк |
| Можно переиспользовать | Нет | В проекте | Где угодно |

### Skill vs Prompt: ключевое отличие

Skill даёт **воспроизводимый процесс**, а prompt полагается на текущее состояние агента.

Без skill:
> "Напиши тест для функции calculateTax."
> Агент пишет тест как умеет — стиль зависит от контекста сессии.

Со skill "test-driven-development":
> "Напиши тест для функции calculateTax."
> Агент загружает skill → следует TDD-циклу (red → green → refactor) → проверяет покрытие → запускает тесты.

## Кейс / пример

Команда разрабатывает микросервис. В AGENTS.md прописано: "Формат коммитов: conventional commits, язык кода — Go, тесты — в отдельных файлах _test.go".

Разработчик загружает skill "writing-tests". Skill предписывает: "Тесты пиши рядом с кодом, имя файла — name_test.go". Skill не конфликтует с AGENTS.md, а дополняет его.

Если бы skill сказал "пиши тесты в отдельной папке tests/", то AGENTS.md бы победил — тесты остались бы рядом с кодом.

## Упражнение

Ты работаешь над проектом, в котором: AGENTS.md запрещает использовать npm, а skill "package-manager" говорит "используй npm". Что победит и почему? Ответ напиши в 2-3 предложения.

1. Расположите в порядке возрастания приоритета: System Prompt, Skill, AGENTS.md.
2. Какой объём инструкций оправдывает создание отдельного skill, а не запись в AGENTS.md?
3. Что произойдёт при конфликте между AGENTS.md и skill?
4. В чём ключевое отличие skill от prompt с точки зрения воспроизводимости?
5. Приведите пример задачи, которая лучше подходит для AGENTS.md, а не для skill.

## Ключевые выводы

- **System Prompt** — базовые правила платформы, низший приоритет
- **AGENTS.md** — проектные инструкции, высший приоритет на время сессии
- **Skill** — загружается по необходимости, средний приоритет
- Иерархия: AGENTS.md > Skill > System Prompt
- Skills хороши для конкретных задач, AGENTS.md — для проекта, System Prompt — для платформы
- Мало инструкций (1-2 строки) → AGENTS.md, много → skill
