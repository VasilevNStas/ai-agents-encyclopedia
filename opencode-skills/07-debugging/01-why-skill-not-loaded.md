# Почему skill не загружается

**Время чтения:** 8 мин

## Суть

Skill не загружается — значит агент его не видит или не считает релевантным. Чаще всего проблема в description, расположении файла или механизме триггеринга. Этот модуль — систематическая диагностика.

## Основной материал

### 5 причин, почему skill не загружается

#### 1. Description не совпал с задачей

Самая частая причина. Агент принимает решение о загрузке на основе семантического сходства между description skill и текстом задачи пользователя.

Пример:
- description skill: "Use when debugging test failures in CI pipelines"
- задача: "Почему падают тесты локально?"
- результат: match слабый — слово "CI" в description, а задача про локальный запуск

**Диагностика:** переформулируй задачу, используя точные слова из description. Если skill загрузился — проблема в описании.

**Решение:** расширь description, добавив синонимы. Используй eval-запросы для проверки [см. урок 03-02](../03-mechanics/02-one-percent-rule.md).

#### 2. Неправильный путь или структура

Skill должен лежать в директории, которую агент сканирует:

```
.opencode/skills/<skill-name>/SKILL.md     # OpenCode (проектные)
~/.cache/opencode/packages/                 # OpenCode (глобальные)
node_modules/superpowers/skills/<name>/SKILL.md  # npm-пакеты
```

**Типовые ошибки:**
- Файл называется `*.skill.md`, а не `SKILL.md` → агент не найдёт
- Имя директории не совпадает с `name` в frontmatter → валидация не пройдена
- SKILL.md лежит прямо в корне, а не в поддиректории с именем skill

**Диагностика:**
```bash
ls .opencode/skills/<skill-name>/SKILL.md
skills-ref validate .opencode/skills/<skill-name>
```

#### 3. SUBAGENT-STOP

Если skill содержит `<SUBAGENT-STOP>`, то при загрузке в дочернем агенте (subagent) он будет пропущен. Это особенность архитектуры — subagent'ы делегируют обнаружение skills родителю.

**Диагностика:** проверь, что skill не запущен внутри subagent.

#### 4. Слишком простая задача

Важный нюанс: агенты обычно применяют skills только к задачам, требующим знаний или возможностей сверх базовых. Простой запрос вроде "прочитай этот PDF" может не триггернуть skill, даже если description совпадает идеально — потому что агент справляется базовыми инструментами.

**Решение:** это нормальное поведение. Skill оправдан для задач, которые без него агент делает плохо.

#### 5. Баг модели (model miss)

Агент может просто "забыть" проверить доступные skills. Это не технический баг, а поведенческий — LLM иногда пропускает этот шаг, особенно при высокой нагрузке на контекст.

**Диагностика:** принудительно вызови `skill("name")`. Если skill загружается и работает — проблема в модели, а не в файле.

### Пошаговая диагностика (4 шага)

1. **Проверь совпадение слов** в description и задаче пользователя
2. **Проверь путь и структуру** — существует ли SKILL.md, валиден ли frontmatter
3. **Проверь SUBAGENT-STOP** — не запущен ли skill внутри subagent
4. **Переформулируй задачу** — используй точные слова из описания. Если skill загрузился — проблема была в семантике

### Инструменты отладки триггеринга

**Eval-запросы (рекомендовано Anthropic):**
Создай набор из 20 запросов (10 должны триггерить, 10 не должны). Прогони каждый 3 раза, вычисли trigger rate. Цель — 90%+ на should-trigger запросах.

Пример:
```json
[
  { "query": "напиши тесты для модуля X", "should_trigger": true },
  { "query": "как переименовать файл", "should_trigger": false }
]
```

**Принудительная загрузка:**
```bash
skill("skill-name")  # OpenCode
Skill("skill-name")  # Claude Code
```

## Кейс / пример

Ситуация: установлен skill для работы с Docker, но при запросе "Собери образ" агент его не использует.

Диагностика:
1. `ls node_modules/superpowers/skills/docker/SKILL.md` — файл есть
2. Читаем frontmatter: `description: "Use when writing Dockerfiles for production"`
3. Задача "Собери образ" не совпадает — нет слова "Dockerfile" и "production"
4. Правим description: "Use when building, running, or debugging Docker containers"
5. При следующем запросе skill загружается

## Ключевые выводы

- Самая частая причина — несоответствие description задаче
- Проверяй путь: директория + SKILL.md, имя совпадает с name
- SUBAGENT-STOP может блокировать загрузку в subagent
- Простые задачи могут не триггерить skills — это нормально
- Для диагностики используй eval-запросы и принудительную загрузку
