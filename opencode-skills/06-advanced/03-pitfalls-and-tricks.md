# Подводные Камни и Трюки

**Время чтения:** 8 мин

## Суть

Skills — мощный механизм, но они хрупки. Skill может не загрузиться, конфликтовать, устареть или быть проигнорирован агентом. В этом модуле — диагностика проблем и трюки для их решения.

## Основной материал

### 5 проблем и их решения

#### 1. Skill не загрузился

**Причины:**
- **Узкое описание (description)** — слова не пересекаются с задачей пользователя
- **Баг модели** — семантическая эвристика дала false negative
- **SUBAGENT-STOP** — дочерний агент пропустил загрузку
- **Путь к файлу невалидный** — SKILL.md перемещён или удалён

**Диагностика (4 шага):**
1. Проверить совпадение слов в description и задаче
2. Проверить путь к SKILL.md — существует ли файл
3. Проверить SUBAGENT-STOP
4. Переформулировать задачу словами из описания

**Решение:** расширить description, добавив синонимы и варианты формулировок.

#### 2. Конфликт инструкций

**Причина:** два загруженных skills дают противоположные инструкции.

**Решение:**
- Сузить описания, чтобы skills не пересекались
- Если должны сосуществовать — объединить в один SKILL.md с условной логикой
- Уточнить description для более точного триггеринга

#### 3. Перегрузка контекста

**Причина:** каждый загруженный skill добавляет токены. Если загружено 5+, контекст переполняется.

**Решение:**
- Сократить SKILL.md: вынести длинные списки в reference-файлы
- Оставить только: цель, gotchas, инструкции, ссылки на reference
- Удалить избыточные skills

#### 4. Устаревшие skills

**Причина:** инструкции в SKILL.md устарели, агент следует старому workflow.

**Решение:**
- Добавить дату в metadata: `metadata: { updated: "2026-05-10" }`
- Вести changelog (CHANGELOG.md)
- Версионирование через semver

#### 5. Агент игнорирует skill

**Причина:** skill загружен, но агент не выполняет инструкции.

**Решение:**
- Проверить AGENTS.md — нет ли инструкции, отменяющей skill
- Переписать в императивном стиле
- Использовать чеклисты с `- [ ]`
- Добавить gotchas-секцию

### 4 трюка

#### 1. Skill-фабрика

SKILL.md, который инструктирует агента написать другой skill:

```markdown
## Инструкция

1. Проанализируй задачу пользователя
2. Создай новый SKILL.md, адаптированный под задачу
3. Сохрани по пути skills/<task-name>/SKILL.md
4. Проверь, что skill загружается
```

Применение: динамическое создание skills под конкретные проекты. Реализовано как официальный `skill-creator` от Anthropic.

#### 2. Metaskill — аудит skills

Skill, который проверяет другие skills на корректность:

```markdown
## Checklist

- [ ] Проверить description каждого skill на ключевые слова
- [ ] Проверить дату last-updated — не устарел ли
- [ ] Проверить пути — все ли SKILL.md существуют
- [ ] Проверить chaining — не ведут ли ссылки на несуществующие skills
- [ ] Проверить конфликты — нет ли противоположных инструкций
```

#### 3. Skill-шаблон

SKILL.md с placeholders, которые агент заменяет перед использованием:

```markdown
---
name: <SKILL-NAME>
description: <DESCRIPTION>
---

## Инструкции

1. <STEP-1>
2. <STEP-2>

## Gotchas

- <GOTCHA-1>
```

#### 4. Hidden skill (security layer)

Skill с очень широким description, который срабатывает почти на любую задачу и проверяет безопасность:

```yaml
description: >-
  Use for any code generation, file modification, or deployment task
```

Внутри — проверки: "Нет секретов и ключей в коде", "Нет hardcoded credentials". Загружается почти всегда, но выполняется только если проверки пройдены.

**Риск:** потребляет контекст. Использовать не больше одного такого на проект.

## Кейс

**Проблема:** Skill "test-driven-development" не загружается на задачу "напиши тесты для модуля авторизации".

**Диагностика:** description TDD не содержит слова "test" — он ориентирован на "feature or bugfix". Совпадения нет.

**Решение:** расширить description — добавить "writing tests", "unit test":

```yaml
description: >-
  Use when implementing any feature, bugfix, OR writing tests,
  before writing implementation code.
```

После изменения skill загружается на задачи про тесты.

## Упражнение

Твой skill не загружается при очевидном совпадении задачи. Опиши пошаговый план диагностики (4 шага).

## Проверь себя

1. Назови три из пяти проблем, из-за которых skill может не работать.
2. Какой трюк позволяет динамически создавать skills под конкретные проекты?
3. Какие четыре шага диагностики нужно выполнить, если skill не загружается?
4. Что такое hidden skill и для чего он используется?
5. Почему не рекомендуется иметь больше одного hidden skill в проекте?

## Ключевые выводы

- 5 проблем: не загрузился, конфликт, перегрузка, устарел, игнорируется
- 4 трюка: skill-фабрика, metaskill, шаблон, hidden skill
- Диагностика начинается с проверки description и путей
- Description должен быть достаточно широким, чтобы захватывать целевые задачи
