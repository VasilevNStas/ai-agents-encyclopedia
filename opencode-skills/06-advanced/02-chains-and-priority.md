# Цепочки и Приоритизация

**Время чтения:** 7 мин

## Суть

Когда агент сталкивается с задачей, он проверяет все доступные skills. Если подходят несколько, возникает вопрос приоритета: какой skill загрузить первым и как разрешать конфликты инструкций.

## Основной материал

### Порядок приоритетов

Когда инструкции конфликтуют, агент применяет жёсткий порядок:

1. **User instructions (AGENTS.md)** — наивысший приоритет
2. **Skills — по релевантности** — чем точнее description совпал с задачей, тем выше приоритет
3. **System prompt** — наинизший приоритет

### Что значит "по релевантности"

Агент оценивает семантическое сходство между description skill и задачей пользователя. Если задача "исправить баг в авторизации", а skill A имеет description "Use when encountering any bug", а skill B — "Use for frontend styling", то skill A получает higher relevance score.

Релевантность — это не точная метрика, а эвристика на основе семантического сходства.

### Конфликт инструкций

Два установленных skills:
- **Skill A** (description: "package manager — используй npm")
- **Skill B** (description: "monorepo — используй yarn для монорепозиториев")

Задача: "добавить пакет в монорепозиторий"

Оба подходят. Skill B точнее совпал (слово "монорепозиторий"). Инструкции Skill B приоритетнее. Агент использует yarn.

### Skill Precedence

Нет поля `priority` в мете SKILL.md. Приоритет определяется исключительно релевантностью описания.

Единственный способ повысить приоритет — сделать описание более специфичным. Чем точнее описание сужает область, тем выше relevance score для задач из этой области.

### Стек вызова

Skills загружаются последовательно, не рекурсивно:

```
Агент → skill A (полностью) → skill A велит загрузить skill B → skill B (полностью) → ...
```

Каждый следующий skill выполняется после полного завершения предыдущего.

### Порядок загрузки при равной релевантности

При равной релевантности skills загружаются в алфавитном порядке по имени файла. Поэтому имена вроде `01-composition.md` не случайны.

## Кейс / пример

Задача: "задеплоить на production после прогона тестов".

Установлены два skills:
- **deployment** (description: "деплой на production")
- **testing** (description: "запуск тестов перед деплоем")

Агент оценивает релевантность:
- deployment: совпадает "деплой" и "production" — высокая
- testing: совпадает "тесты" — средняя

Загружается первым deployment (выше релевантность). Внутри может быть HARD-GATE: "Не деплоить без тестов". Агент проверяет — не выполнено. Прерывается. Загружает testing. Тесты пройдены — возвращается к deployment.

## Упражнение

У тебя два навыка: "deployment" и "testing". Оба могут сработать на задачу "задеплоить после тестов".

1. Как агент решит, какой загрузить первым?
2. Как изменить описание testing, чтобы он загружался первым?

## Проверь себя

1. Расставь приоритеты по убыванию: System prompt, Skills, AGENTS.md.
2. Что определяет приоритет skill при равной релевантности описаний?
3. Как изменить description skill, чтобы он загружался раньше?
4. Как агент разрешает конфликт инструкций между двумя загруженными skills?
5. В каком порядке skills загружаются при равной релевантности?

## Ключевые выводы

- Приоритет: AGENTS.md > Skills (по релевантности) > System Prompt
- Нет поля priority — релевантность определяется description
- При равной релевантности — алфавитный порядок
- Стек вызова последовательный, skills не выполняются параллельно
- Единственный способ повысить приоритет — специфичный description
